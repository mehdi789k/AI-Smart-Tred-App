# طراحی مدیریت امن تنظیمات محیط در داشبورد

## هدف

صفحهٔ `Settings` داشبورد Streamlit باید بتواند فایل `.env` اجرای محلی را به‌شکل
کنترل‌شده مدیریت کند: مشاهدهٔ کلیدها، ویرایش مقادیر، حذف فایل، و بازنشانی به
پروفایل‌های `demo` و `live`. مقدار خام credentialها نباید در رابط یا لاگ افشا
شود.

## دامنه و مرزها

- پیاده‌سازی در بستهٔ `src/python/dashboard/` انجام می‌شود.
- فایل واقعی `.env` فقط از مسیر ریشهٔ پروژه resolve می‌شود و path traversal رد
  خواهد شد.
- این قابلیت endpoint جدید FastAPI ندارد؛ بنابراین قرارداد API تغییر نمی‌کند.
- تغییر `.env` در فرایند فعلی به‌طور خودکار reload نمی‌شود و رابط باید نیاز به
  restart سرویس‌ها را واضح اعلام کند.

## احراز هویت و افشای داده

- بخش مدیریت با متغیر `DASHBOARD_ADMIN_TOKEN` محافظت می‌شود. نبودن این متغیر
  باعث قفل‌بودن بخش است، نه دسترسی آزاد.
- توکن فقط با مقایسهٔ ثابت‌زمان و از طریق ورودی password بررسی می‌شود و در
  `st.session_state`، لاگ یا فایل ذخیره نمی‌شود.
- کلیدهای حساس شامل الگوهای `PASSWORD`، `TOKEN`، `SECRET`، `DATABASE_URL` و
  `PRIVATE_KEY` هستند. مقدار فعلی آن‌ها همیشه به‌صورت `********` نمایش داده
  می‌شود؛ برای تغییر باید مقدار جدید وارد شود.
- کلیدهای ناشناخته یا خارج از فهرست امن `.env.example` اجازهٔ ایجاد/ویرایش
  ندارند، مگر آن‌که کلید از قبل در فایل موجود باشد و با الگوی نام معتبر
  (`[A-Z][A-Z0-9_]*`) مطابقت کند.

## عملیات فایل

ماژول مستقل `env_manager.py` توابع typed برای این عملیات فراهم می‌کند:

1. خواندن خطوط `KEY=VALUE` با حفظ کامنت‌ها و خطوط ناشناختهٔ قابل‌قبول.
2. تولید view مدل‌شده با ماسک‌کردن مقادیر حساس.
3. به‌روزرسانی کلیدهای غیرحساس و جایگزینی صریح کلیدهای حساس.
4. حذف `.env` فقط پس از تأیید دوبارهٔ رابط.
5. بازنشانی اتمیک به پروفایل `demo` یا `live`.

قبل از هر write، یک backup زمان‌دار در `backups/` ایجاد می‌شود؛ write با فایل
موقت در همان directory و `os.replace` انجام می‌شود. خطای backup یا replace باید
به کاربر گزارش شود و نباید پاسخ موفقیت تولید کند.

## پروفایل‌ها

- `demo`: `APP_ENV=development`، `MT5_DEMO_ENABLED=true`,
  `MT5_AUTO_TRADING_ENABLED=false`، `MT5_ENABLED=false` و محدودیت‌های محافظه‌کار
  مطابق `.env.example`. مقادیر credential خالی باقی می‌مانند.
- `live`: `APP_ENV=production`، `MT5_DEMO_ENABLED=false` و تنظیمات عملیاتی
  live مطابق `.env.example`. مقدارهای حساس از `.env` فعلی حفظ می‌شوند؛ اگر
  وجود نداشته باشند خالی می‌مانند. `MT5_AUTO_TRADING_ENABLED` همچنان
  `false` می‌ماند تا فعال‌سازی جداگانه و صریح انجام شود.

بازنشانی پروفایل به معنی اعمال فایل است، نه reload کردن process یا صدور مجوز
معامله.

## رابط کاربری

در صفحهٔ Settings یک expander با عنوان مدیریت محیط اضافه می‌شود:

- وضعیت قفل/باز بودن و زمان آخرین تغییر نمایش داده می‌شود.
- پس از احراز هویت، جدول کلیدها، مقدار نمایش‌داده‌شده و کنترل ویرایش ارائه
  می‌شود.
- دکمه‌های `Save`, `Delete .env`, `Reset demo`, `Reset live` با تأییدهای مناسب
  و پیام نیاز به restart نمایش داده می‌شوند.
- حذف و reset هنگام فعال‌بودن trading، معامله‌ای ارسال نمی‌کنند و باید با
  هشدار توقف سرویس همراه باشند.

## خطا و ثبت رویداد

خطاهای invalid input، permission، backup، parse و filesystem با پیام قابل‌فهم
به کاربر نشان داده و با نام عملیات و مسیر منطقی (بدون مقدار secret) لاگ می‌شوند.
هیچ `except Exception` گسترده یا fallback موفقیت‌آمیز استفاده نمی‌شود.

## آزمون و مستندات

- unit test برای parser، masking، حفظ secret، پروفایل‌ها، atomic write و
  path traversal.
- تست UI/Streamlit برای قفل بودن بدون token و نمایش امن بخش پس از احراز هویت.
- تست حذف و reset با فایل موقت.
- به‌روزرسانی `docs/ARCHITECTURE.md` و راهنمای اجرای مرتبط؛
  `docs/API_CONTRACT.md` بدون تغییر می‌ماند.
